# Specification completeness — and the roadmap it implies

This is the project's north star: every protocol obligation namespy could
plausibly take on, with an honest status against the code and tests at
`HEAD`. It is deliberately blunt about gaps — three of them change the
security properties of anything built on top, and pretending otherwise would
make this document useless as a planning tool.

**The honesty rule:** ✅ requires a named test, and a row may only say ✅
when that test would fail if the behaviour regressed. Reading code and
agreeing is not enough; that is how "EDNS is decoded but not sent" nearly
became "EDNS is done".

Legend: ✅ implemented and pinned by tests · 🟡 partial (what is missing is
stated) · ⬜ not implemented · ▫️ deliberate non-goal.

When you change behaviour that a row describes, update the row in the same
commit — the same rule [`CONTRIBUTING.md`](../CONTRIBUTING.md) states for
code citations. [`rfc-map.md`](rfc-map.md) remains the deep RFC 1034 §5.3.3
walkthrough; this document is the cross-specification survey.

Every P1 is now shipped: bailiwick, EDNS options and OPT echo outright, QNAME
minimisation opt-in, and RFC 9520's failure cache last — the item that had
replaced the others at the top, because it was the one whose absence was visible
to people who had never run this code. It is about how much traffic a resolver
sends other people's nameservers: before it, every lookup that walked into a dead
zone started the hammering again from zero, and the next name beneath that zone
re-asked its parent as though nothing had happened. All three of that RFC's rows
are ✅, §3.1's retry ceiling included: the ceiling is per transport, so a silent
server costing one UDP query and one TCP attempt is what the text allows, and
`test_silence_is_tried_once_per_transport_and_no_further` is what keeps this
project from talking itself out of that reading later.

Everything below changes the answers this resolver gives or the transports it can
use: the SVCB codec has landed, so the cheap correctness items still open are IDNA and
wildcard synthesis, then DNSSEC, which remains both the largest trust gap and by
far the largest project.

## The second horizon: what to build once compliance is boring

Sections 1–9 are about *obligations* — what the specifications require. This
table is what the stack now makes *possible*: capabilities that ride the
machinery already shipped (the EDE vocabulary, the TLS client doors, the
trace, the validator, the option pipeline) instead of opening new protocol
surface blind. The honesty rule still applies, and the survey that produced
this table tested itself against it: **four remembered RFC numbers were wrong**
(RPZ's is RTP/TTML, the filtering experience RFC is MPLS, the DNS log-record
RFC is COSE, the blocklist-etiquette RFC is SIP), and the corpus check
settled each row's anchors the same way the citation sweeps settle code's.
Seven of the nine rows below are ✅ — U1, U2, U3, U4, U5, U8 and U9
shipped. U6's serve leg has landed too (increment AA), but its row
stays uncrossed until a zone can be transferred, not just served;
U6's transfer leg and U7 remain to do — and every row, shipped or
not, cites documents that answered `info()` and `search()` at planning
time, October 2026.

**Order of attack, with reasons.** U8 first (it is a correctness bug wearing a
feature's clothes); then U1 → U2 in one pair, because the hook without the
flagship reflex looks like plumbing with nothing to show and the reflex
without the hook is impossible. U5 followed, shipped as increment W — the
first increment whose test suite runs *both ends of TLS with one codebase*.
U3 then shipped as increment X, landing on the EDE machinery that already
exists: W's SERVFAIL-plus-EDE-22 relay was that vocabulary's first use on
the server's own failures, and filtering is its use on the operator's.
U4 followed as increment Y, riding the same pipeline for free — its
`origin` vocabulary is X's ladder read from the egress door. U9 shipped
as increment Z, the consumer half of the same etiquette: what X emits
and Y logs, a list reader must believe — three states, one reversal,
codes passed through uninterpreted. U6 and U7 are each a
campaign, not an increment — U6 earns its size by feeding U3 and U9 with real
zone data, U7 by being the only row that makes namespy useful on a network
with no DNS in it at all. An `examples/` directory grows with the
capabilities — U2's `dynamic_responders.py` and U9's `blocklist.py`
already run against the loopback server this project ships, one
self-contained script per capability; U7's lands with U7 (U5's example is its test

## The third horizon: composition, ergonomics, and the researcher's toolkit

Sections 1–9 are obligations; the second horizon was capability. This table is
what the *users* ask for — assembled from a landscape survey (October 2026)
whose evidence lives in `docs/research.md` (a gitignored working note) and
whose decisions live in [`strategy.md`](strategy.md). The framing rule the
survey produced: **namespy competes on correctness and instrumentation, never
throughput** — the incumbents' codecs are bug-changelogs, their rate limits
throttle the wrong counter, their brute-forcers treat DNSSEC denials as opaque,
and none of them says *how it knows* an answer is what it claims to be. The
layering rule: core stays the RFC implementation; `namespy.apps.*` composes it;
`examples/` configure it — a pattern graduates upward only on second use (the
`_reversed_labels` precedent).

Three of the ten rows below are ✅ — W1 shipped as increment AB, W2 as increment
AC, and W3 as increment AD — and the other seven are planning rows in the second
horizon's sense: anchored where a document speaks, convention-labeled where none
does, and uncrossed until a named test would fail on regression.

**Order of attack, with reasons.** W1 first: every later row inherits its
drive from the engine, and its test suite settles the hard parts (thread
affinity, timeout parity, the nested-loop trap) once rather than per-module.
W2–W5 are one arc — client ergonomics, then the forward table the survey says
is the single missing noun, then the compositions that prove it. W6 leads the
research tier because it is flagship-shaped and ships with zero new core code;
W7 follows (its wildcard filter reads through W6's denial machinery); W8–W9 are
reporting layers over verdicts already formed; W10 lands last because a CLI
surface designed before the apps tier settles would design the wrong flags.
U6's transfer leg and U7 stay as they were — campaigns on their own merits,
and W8's AXFR probe waits on the former.

**Declined with reasons, in the house style:** RRL/rate limiting (stays ▫️ —
the server is a loopback fixture; W9's tarpit must argue its corner as
refusal-shaped delay, not flood mitigation); DoH server (stdlib has no HTTP/2 —
U4 shipped the *client*; serving 8484 would mean restating its requirement
rather than silently failing it); CoAP (no server here talks to it);
trust-anchor *automation in the fetch loop* — RFC 5011's state machine shipped
in `maintenance.py`, and wiring it into resolver fetch remains a scheduler
decision with no document asking for one; raw-throughput competition (the
C+epoll figure is unreachable and irrelevant to correctness work); DoQ and
DNSCrypt (no QUIC dependency, no new wire dependency, full stop); DGA/tunnel
*classifiers* (namespy is the collection and verification end, not another
model); ambient resolv.conf/hosts reading in core (deployment behavior must
never be the library's default — opt-in at the apps door).
